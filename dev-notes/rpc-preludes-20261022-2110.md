# `rpc_core_v1::preludes` 与文档缺口清单

日期：2026-10-22 21:10

## 1. prelude 内容

新增 `rpc_core_v1::preludes`，一次 glob 即可覆盖协议、客户端、服务端最常用的入口：

```rust
use rpc_core_v1::preludes::*;
```

导出分组：

- 配置：`ClientConfig`、`ServingConfig`、`TrDefaultDock`、`TrUserConn`、
  `TrRpcClientConfig`、`TrServingConfig`、`TrServingAllocConfig`、
  `DefaultRpcAllocConfig`、`DefaultServingAllocConfig`；
- 客户端：`MptpClient`、`ClientProxy`、`ServiceSelector`、`TrRpcClientExt`；
- 服务端：`MptpServer`、`Router`、`RouterCtx`、`RpcRouter`、`RpcCallCtx`、
  `RpcServiceCtx`、`TrPathHandler`；
- 协议与错误：`RpcError`、`RpcResult`、`TrRpcInterface`、`Status`；
- 取消：`TrMayCancel`、`TrCancellationToken`、`NonCancellableToken`；
- 宏与派生：`gen_may_cancel_future`、`TrEncodable`、`TrDecodable`；
- 常用底座：`Shared`、`CoreAlloc`、`TrConnection`（`bind_async` 等连接方法所需）；
- 服务端扩展：`TrRpcService`、`TrRpcCallCtx`、`TrReqHandler`、`RouterError`。

prelude 只转出，不改变可见性、trait 约束或宏行为。

## 2. 已确认的文档状态

`cargo rustdoc -p rpc_core_v1 -- -D missing_docs` 已通过：core 自身的公共项（含 prelude）
都有模块 / 条目文档。

`mptp_smux` 中 prelude 涉及的 `MptpClient`、`MptpServer`、`Router`、`RouterCtx`、
`RouterError`、`TrPathHandler` 都有文档；`Router` 还有可编译示例。

`abs_rpc_serv::service::{TrRpcCallCtx, TrRpcService}` 有中英文说明；`abs_rpc_serv::config`
模块文档已补齐。

## 3. 下一步要补的文档

以下项目已被 prelude 导出，但文档仍偏薄或缺少条目级说明。按优先级排列：

1. `abs_cancel::TrMayCancel`
   - trait 级只有英文说明；
   - `MayCancelFuture` / `MayCancelOutput` / `may_cancel_with` 没有条目级文档；
   - 建议补：`'a` / `'f` 生命周期含义、令牌如何传播、取消后的返回语义，并加一个
     `NonCancellableToken` 的示例。

2. `abs_cancel::TrCancellationToken`
   - trait 级有英文说明；
   - `Cancellation` / `ChildToken` 两个关联类型与四个方法都没有条目文档；
   - 建议补：`child_token` 与父令牌的关系、`cancellation` future 的完成条件、
     `can_be_cancelled` 与 `is_cancelled` 的区别。

3. `abs_cancel::NonCancellableToken`
   - 类型只有一行英文说明；
   - `new` / `shared_mut` / `child_token` / `cancellation` 等方法缺少文档；
   - 建议补：它只用于「明确不取消」的占位路径，不应作为默认选择。

4. `abs_mm::CoreAlloc`
   - 类型只有一行英文说明；
   - `new` / `allocate` 没有文档，`deallocate` 的 `# Safety` 是英文；
   - 建议补：系统分配器语义、`AllocatorClone` 行为、失败返回 `AllocError`。

5. `abs_mptp::Status`
   - `new` 没有条目文档；
   - 若干状态常量（如 `BadRequest` / `Unauthorized` / `Forbidden` / `NotFound` /
     `InternalServerError` / `NotImplemented` / `BadGateway` / `ServiceUnavailable`）
     没有说明，已有的说明也多为英文；
   - 建议补：数值、线上语义、与 `RpcError::status()` 的映射关系。

6. `rpc_core_v1::serving::RpcServiceCtx`
   - 有类型文档，没有示例；
   - 建议补：当前为空上下文、业务数据应通过闭包捕获、未来扩展点的使用方式。

7. `rpc_core_v1::serving::RpcRouter`
   - 示例目前是 ` ```ignore `；
   - 建议改成可编译示例（用假 service + `ReadyMayCancel`），并说明
     `add_service` 的「后加入优先」规则。

8. `abs_rpc_serv::service::{TrRpcCallCtx, TrRpcService}`
   - 有 trait 文档，但没有示例；
   - 建议补：一个最小 `TrRpcCallCtx` 实现，以及 `service_of` 生成实现的形状。

9. `mptp_smux::RouterCtx`
   - 有类型文档，没有示例；
   - 建议补：`Router::call(|ctx| ...)` 的装配示例，以及它当前不携带运行期数据。

10. `denco_macro::{TrEncodable, TrDecodable}`
    - crate 级和 derive 级文档已有；
    - 缺少 `# Examples` / `# Panics` 章节；属于「可选补强」，不是阻塞项。

11. `gen_mcf2::gen_may_cancel_future`
    - 文档已比较完整，暂不需要处理。

12. `abs_smux::TrConnection`
    - prelude 为 `bind_async` 等连接方法导出了它；
    - 类型只有一行英文说明，关联类型与方法缺少条目文档；
    - 建议补：`bind_async` / `connect_async` / `accept_async` 的语义与错误类型。

## 4. 不在 prelude 内、但本轮扫描发现的缺口

- `mptp_smux::messaging::wire_` 的 4 个 future 结构体没有文档；
- `mptp_smux::ring_prepare_` 有一个关联类型没有文档；
- `abs_mptp` 的 `client` / `messaging` 模块与若干 future 结构体、关联类型缺少文档；
- 这些不属于本次 prelude 导出面，后续可按模块优先级处理。
