# matchit 的 no_std 移植与 router 统一方向

**当前结论**：`matchit_route` 是 `matchit` 0.9.2 的 `no_std` 移植版。路由树与节点值
放在 router 自有的 `bumpalo` arena 里，字符串错误信息使用 `abs_str` 的
`String<Global>`，一次性数据才走全局分配器。下一步删除 `rpc_router_trie`，让
`matchit_route` 成为项目里唯一的路径匹配算法。

## 1. 为什么 fork 而不是直接依赖 matchit

上游 `matchit` 直接使用 `std::vec::Vec`、`std::string::String`、`VecDeque` 与
`std::error::Error`，无法在 `no_std` 下使用；它的 `Node<T>` 也没有可注入的分配器
参数。移植面比“给上游提一个 feature”小：树的结构与算法保持不变，只替换容器与
分配来源。上游的双许可证（MIT AND BSD-3-Clause）随 crate 保留。

## 2. 内存模型

### 2.1 router 自有 arena

`Router<T>` 持有 `Box<bumpalo::Bump>`，路由节点全部从这块 arena 分配：

- `Node.prefix` / `indices` / `children` / `remapping` 用
  `bumpalo::collections::Vec`；
- 节点值用 `bumpalo::boxed::Box<UnsafeCell<T>>`，因此 `Router` 析构时先运行 `T` 的
  `Drop`，再释放 arena；
- `Router` 的字段顺序是 `root` 在 `arena` 之前，Rust 按声明顺序析构，保证节点不会
  访问已经释放的 arena。

`Bump` 放在 `Box` 里，堆地址在 `Router` 移动时保持不变；`Node` 内部的
`&'static Bump` 只是把“由 router 保活”写成生命周期，外部无法取得这个引用。字段全部
私有，`Router` 也不实现 `Deref` 到 arena，因此这个 `'static` 不会泄漏给调用方。

### 2.2 `T: 'static`

节点值存在 arena 里，`Node<'static, T>` 要求 `T: 'static`。这对服务端路由是自然
约束（handler、`Arc`、`&'static str` 都是 `'static`），但比上游更严格；文档与
`Router` 的泛型约束都显式写出。

### 2.3 一次性分配

以下数据不进入 router 的长期 arena，而是临时使用全局分配器，用完即释放：

- `Params` 超过 3 个参数时的 `alloc::vec::Vec`；
- 匹配回溯用的 `Skipped` 栈；
- `InsertError::Conflict` / `MergeError` 的错误文本（`abs_str::String<Global>`）；
- `Router::for_each` 的 BFS 队列。

这样匹配热点不会向长期 arena 泄漏内存。

### 2.4 `Send` / `Sync`

`bumpalo::Bump` 是 `Send` 但不是 `Sync`，`Node` 内部的 `&Bump` 让自动 trait 推导
得到 `!Send + !Sync`。本 crate 手动实现：

- `unsafe impl<T: Send> Send for Router<T>`：`Router` 独占 arena，移动到另一个线程
  不会与旧线程共享；
- `unsafe impl<T: Sync> Sync for Router<T>`：`&Router` 只暴露 `at` 等只读匹配，
  `insert` / `remove` / `merge` 都要求 `&mut self`，不会并发触碰 arena 分配器。

两处 `unsafe` 都写了安全注释；测试 `arena_` 里有编译期 `Send + Sync` 断言。

## 3. `abs_str::String<Global>` 的取舍

`matchit` 的 `String` 出现在三处：插入参数、冲突错误、`for_each` visitor。

- 插入参数改为 `impl AsRef<str>`：直接复制进 arena 的字节 `Vec`，不再先构造 `String`；
- `for_each` 的 visitor 改为 `&str`，路径只在回调期间有效，不分配；
- 冲突错误保留 owned 字符串，但换成 `abs_str::str_alloc::String<Global>`，这样 crate
  仍然 `no_std`，且错误可以跨出 `Router` 的借用期。

上游用 `String::truncate`（字节语义）处理冲突路径；`abs_str::String::truncate` 是
字符语义，不能直接替换，所以路径本体继续用 `bumpalo::collections::Vec<u8>`，只在
最终生成错误文本时转成 `abs_str::String`。

### 3.1 从 0.8.6 升级到 0.9.2

初版移植按 0.8.6 完成，随后按最新版 0.9.2 同步。0.9.2 的算法改动集中在**插入冲突
规则**：`Node::insert` 用 `InsertState` 同时跟踪父节点与当前子节点，以便在前缀参数与
后缀参数指向同一路径段时判定歧义；新增 `prefix_wild_child_in_segment` /
`wild_child_in_segment` / `suffix_wild_child_in_segment` 三个辅助判断。匹配、删除与
遍历算法不变。空树判定也从 `prefix.is_empty() && children.is_empty()` 改为
`value.is_none() && children.is_empty()`，修复空路由（`""`）无法再插入的问题。

移植版同步了这些改动，并保留 no_std 适配（`Node::new_in`、bumpalo 容器、
`Box<UnsafeCell<T>>`）。0.9.2 新增的 `Param` / `ParamsIter` Debug 实现也一并移植。

## 4. 与上游的 API 差异

| 项 | 上游 | 本移植 |
| --- | --- | --- |
| `Router::insert` / `remove` 入参 | `impl Into<String>` | `impl AsRef<str>` |
| `InsertError::Conflict.with` | `std::string::String` | `abs_str::String<Global>` |
| `Router::for_each` visitor | `FnMut(String, T)` | `FnMut(&str, T)` |
| 参数超过 26 个 | `panic!` | `InsertError::TooManyParams` |
| `Router<T>` 约束 | 无 | `T: 'static` |
| 私有字段命名 | 上游命名 | 保留上游命名，便于逐行对照算法 |

- 新增 `tests/arena_.rs` 6 条：值析构、移动后 arena 稳定、`Send + Sync`、克隆使用
  独立 arena、`for_each` 还原原始路径、冲突错误使用 `abs_str` 字符串；

## 6. 第 3 步：删除 `rpc_router_trie`，统一路径匹配

第 3 步已完成：

- 删除 `rpc_router_trie` crate（`PathTrie`、`RpcRouter`、`RpcRouterError`）及其 workspace
  member；
- 删除只服务于它的队列版契约 `TrRpcRouter` / `RpcRouterHandler` / `RpcJob` /
  `ServiceRoute` / `TrRpcServiceRoute` / `RpcRouteError` / `RpcDispatchError` /
  `K_DEFAULT_SERVICE_QUEUE_CAP`；
- `mptp_smux::serving::Router` 把每条 interface 前缀展开成 `matchit_route` 的
  “精确路径 + `{*rest}` catch-all”，用 `OnceLock` 持有索引表；
- `rpc_core_v1::serving::RpcRouter` 把每个 service 的 `SERVICE_PATH` 登记进
  `matchit_route`，首次匹配时用 `OnceLock` 构建，随后按索引分派具体 service；
- 两个 router 的前缀 / service 路径都是静态的，登记前把 `{` / `}` 转义成字面量；
  重复路径由列表头（后登记）先注册，冲突时忽略，保持“后登记生效”的旧语义。

于是框架里只剩 `matchit_route` 一套路径匹配算法；需要队列 / 背压时在 handler 或 target
内部实现，不再拆出第二种 router。两个 demo 里的本地 router 仍是“手写实现示例”，不属于
框架路由层，未在本轮迁移。
